Architecture walkthrough

How one request moves through ClearHR

Use this map while presenting: it shows where the agent makes decisions, where MCP tools run, and how returned evidence becomes a cited answer.

Normal LLM-enabled path
  1. 01 · Request Browser sends a question POST /chat carries the synthetic question, employee ID, and mock-action confirmation.
  2. 02 · Guardrails Agent orchestrator Applies identity and safety checks, then selects the LLM or the deterministic fallback.
  3. 03 · Plan OpenAI LLM planner Receives discovered MCP tool schemas and decides which evidence is needed next.
  4. 04 · Retrieve MCP client → FastMCP server Calls typed tools over stdio / JSON-RPC to retrieve RAG policy evidence or mock records.
  5. 05 · Use results Structured results return to the LLM The planner can use the evidence or request another bounded MCP tool call.
  6. 06 · Explain Reviewable answer in the browser ClearHR returns the final answer, citations, and exact MCP tool trace for review.
Safe alternate paths.

Sensitive workplace-conduct reports enter the deterministic safety gate before any LLM call. If the provider is unavailable, the deterministic planner uses the same MCP tool boundary and still returns visible evidence.
